# switchbot-aircon 仕様

SwitchBot の赤外線リモコン(エアコン)を、HTTP の簡単な API で操作・参照する Bun 製サーバー。
仕様を変えたときは、このファイルも必ず更新する。

## 構成

| ファイル | 役割 |
|---|---|
| `index.ts` | サーバー本体(Hono)。環境変数の検査、エアコンの状態の取得・送信、HTTP のエンドポイント |
| `account.ts` | SwitchBot アプリの内部 API(`account.api.switchbot.net`)のログイン・トークン更新・ユーザー情報 |
| `devices.ts` | `bun run devices`。公式 API からデバイス一覧を出し、`DEVICE_ID` を調べるための補助 |

実行は `bun run start`(= `bun run index.ts`)。`bun run build` で単一の実行ファイルにもできる。

## 設定(環境変数)

| 変数 | 必須 | 内容 |
|---|---|---|
| `LISTEN` | はい | `ホスト:ポート`(例 `0.0.0.0:10510`) |
| `SWITCHBOT_TOKEN`, `SWITCHBOT_SECRET` | はい | 公式 Cloud API の認証。エアコンへのコマンド送信に使う |
| `SWITCHBOT_EMAIL`, `SWITCHBOT_PASSWORD` | はい | アプリ内部 API のログイン。リアルタイムの状態の取得に使う。2段階認証は非対応 |
| `DEVICE_ID` | はい | エアコン(赤外線リモコン)のデバイス ID |

どれかが欠けていると、メッセージを出して終了コード 1 で終了する。

## 状態

```
temperature: 16〜30   (数値)
mode:        auto | cool | dry | fan | heat
fanSpeed:    0〜5     (0 = 自動)
power:       true | false
```

モードの内部コードは auto=1、cool=2、dry=3、fan=4、heat=5。
SwitchBot の内部 API では風量が 1〜6(1 = 自動)、電源が 1/0 で返るので、取得時に `fanSpeed - 1` と真偽値に変換する。
温度が `-100`(不明)で返ったときは、直前の値を使う(起動直後は 16)。

## 起動時の動作

1. アプリの内部 API にログインし、ユーザー情報を取得してログに出す。
2. 公式 API のクライアントを作る。
3. エアコンの現在の状態を取得して保持する(以後 `state`)。

## 内部 API のトークン管理

状態を取る前に、アクセストークンの期限(`expiresIn`)が切れていれば更新する。
ログインから `refreshExpiresIn` が過ぎていれば、同じ `deviceId` で再ログインする。そうでなければリフレッシュトークンで更新する。

## HTTP のエンドポイント

読み取りは GET、変更は**メソッドを問わず**(`app.all`)受け付ける。

| パス | 動作 |
|---|---|
| `GET /` | 現在の状態を JSON で返す |
| `GET /power` | `on` / `off` |
| `/power/:power` | `on` か `off` に設定。ほかは 400 |
| `GET /temperature` | 温度(数値の文字列) |
| `/temperature/:temperature` | 16〜30 の数値に設定。範囲外・数値でないなら 400 |
| `GET /fan-speed` | 風量 |
| `/fan-speed/:fanSpeed` | 0〜5 の整数に設定。範囲外・整数でない・空なら 400 |
| `GET /mode` | モード名 |
| `/mode/:mode` | `auto`/`cool`/`dry`/`fan`/`heat` のどれか。ほかは 400 |
| `/parameter/:parameter` | `温度,モード,風量,on|off` をまとめて設定。形式が違う・値が不正なら 400 |

- 変更は成功すると本文 `OK`(200)。
- 読み取りは、状態の取得に失敗してもエラーにせず、保持している直前の値を返す(エラーはログに出す)。
- 変更の送信は、公式 API の `setAll` コマンドで `温度,モード,風量+1,on|off` の文字列を送る。送信に失敗したときのエラー処理はない(例外はそのまま 500 になる)。

## セキュリティ上の注意(現状)

- **エンドポイントに認証がない。** ネットワークに届く相手は誰でもエアコンを操作できる。`LISTEN` は信頼できる LAN だけに向けること。
- 変更が GET でもできるため、Web ページの `<img src>` などから操作される恐れ(CSRF)がある。
- 認証情報(トークン、シークレット、メール、パスワード)は環境変数だけで持ち、ログには出さない。
- ログには検証済みの値だけを出す(URL の生の入力は出さない。ログの改行注入対策)。
